What was measured

Four operator questions were written as eval cases in evals/, each with regex graders so correctness is checked mechanically (the count question is graded by hand: all six runs answered 450). Each case ran three times per arm through claude -p --output-format stream-json in a fresh, empty config directory, so no other MCP servers, skills or project files were in context. File tools were disabled in both arms: the lean agent had to use rt_ref, the stock agent the server's own discovery tools.

The one place lean loses is the discovery question. Both arms answer from a catalog, so the payload is similar, and the lean agent spends an extra turn invoking the skill. That turn costs about 2k tokens; it is what buys the one-call behaviour on the data questions.

Where the tokens go, and where they stop going

A Claude Code run re-sends the whole conversation on every assistant turn. A tool result therefore costs its size once when it arrives and again on every later turn. Two levers move the bill: how many turns a question takes, and how many characters each tool result drops into the context. The plugin works on both.

No discovery round tripsThe stock agent called describe_odata_entity_set Shipment (7,428 chars) in 9 of 12 runs before its first real query, plus list_odata_entity_sets and search_endpoints. The lean agent reads names from the bundled reference through rt_ref, offline, 200 to 900 chars per lookup, and in the data questions did not look anything up at all: the skill's recipes carried the names. Measured: 3.3 → 1.2 realtime calls per question.
One query with select and a nested expandThe skill's recipe fetches containers, events and event labels in one call: expand containers($select=containerNumber),events($select=actualDate,expectedDate,locationUnlocode;$expand=code($select=code,actualLabel)). The stock agent needed 7 calls and 24k chars for the same answer, including a 6k-char unselected events expand and a separate EventCode lookup. Measured on containers + events: 196k → 54k input tokens, 14.7 → 5.0 turns.
select is mandatory, nulls and noise strippedrt_query refuses a call without select. Responses lose @odata.context, concurrencyStamp and every null field. A five-row Shipment page is 8,120 chars unselected, 908 chars selected, 149 chars selected and compacted. Measured: tool payload per question 10,732 → 860 chars.
Known server bugs refused before the round tripisMilestone inside a nested $select, $orderby inside expand() and multi-or raw filters all return opaque 500s from the server. The proxy now rejects those shapes locally with the fix in the message, and appends the known causes to any other server error. Before this guard, one lean run wandered through 12 tool calls and failed; after it, all runs are one call.
Upstream calls serialisedThe realtime host fails when several requests arrive at once while each alone succeeds. The proxy chains upstream calls, so an agent may still fire tools in parallel.

Savings that depend on the client

Claude Code loads MCP tool schemas lazily through ToolSearch, so the 38 stock schemas are not in context until searched for. Clients without deferred loading (Claude Desktop, Cursor, Codex, ChatGPT connectors, most custom agents) inject every tool schema into every request. There the proxy's smaller surface is the largest single saving, and it is paid on every turn of every conversation.

Evidence from the server side

  • Audit logs. Every rt_query and rt_call is exactly one POST /mcp in the ABP audit log (filter URL mcp, user admin). The proxy adds no requests; it removes the discovery ones. 543 /mcp requests logged since 28 Aug for this tenant, most of them today's reference build and benchmark.
  • API keys. Three keys exist (n8n Test Key, ChatGPT Dennis, MyMCPKey). The plugin uses the first through the RT_API_KEY environment variable; the key is not in the repository.
  • Reference coverage. 960 endpoints in the catalog, 62 OData entity sets, 40 nested types, 575 DTOs, regenerated by scripts/build-reference.py. Four entity sets the server lists but rejects (OrganizationUnit, IdentityUser, Tag, CalculatedRevenue) are flagged !NOT-QUERYABLE so agents do not spend a call on them.

Caveats

  • Absolute token counts include Claude Code's own system prompt (roughly 15k tokens per turn in an empty config directory). The per-question saving is therefore mostly a turn-count saving; the payload saving compounds on top through re-sends.
  • Cost is sensitive to prompt-cache state (1-hour cache writes are billed higher than reads). Runs were interleaved per arm, not randomised. Treat the cost delta as indicative, the token and call deltas as exact.
  • Skill invocation is not deterministic: in 3 of 12 lean runs the agent went straight to the tools without invoking the skill. The proxy's tool descriptions and preflight guards now carry the critical recipes so the outcome no longer depends on it.
  • claude plugin eval exists and would run this comparison natively, but it is early access and not enabled on this account. The harness reproduces its shape: fresh config dir per run, plugin under test only, regex graders, exact usage from the API.
